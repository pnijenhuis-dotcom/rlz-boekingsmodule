Ontwerpnotities (bouwnorm ná akkoord): ① De 5-cijferige code is het anker: hij ontgrendelt lokaal een toestel-gebonden sleutel die het bestaande apparaat-token/de passkey beschermt — de code gaat nooit naar de server, er is dus geen server-side pincode-opslag of brute-force-apparaat nodig, en de kill-switch per apparaat blijft onverkort werken. ② Harde eis: sleutelopslag toestel-gebonden, expliciet NIET aan de biometrie-set (iOS: géén biometryCurrentSet; Android: setInvalidatedByBiometricEnrollment=false) — Face ID-falen of een nieuw ingeschreven gezicht mag nooit uitsluiten; de code werkt altijd. ③ Biometrie is puur gemak (scherm 4); weggetikt of mislukt → scherm 5. ④ 5 foute codes = sessie + code lokaal gewist + audit-event, herstel = verse kantoor-link (bestaand poortwachter-model, geen selfservice). ⑤ De wachtwoordstap vervalt volledig uit de activatie (herziet de atomaire flow van 28-08: de code-keuze vervangt het wachtwoord; de passkey-registratie gebeurt onder water bij stap 3, zonder eigen scherm). Voorwaarden-akkoord blijft server-side afgedwongen. ⑥ Zwakke reeksen (12345, 00000, 11111…) geweigerd met vriendelijke tekst. ⑦ Zelfde patroon als Vastly (referentie-mockup) = platform-consistent. ⑧ Vereist een kleine native biometrie-/keystore-module → meeliften met de volgende store-build (bv. samen met geofence v1.1).
